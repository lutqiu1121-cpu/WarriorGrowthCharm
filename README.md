# 战士成长饰品拓展（WarriorGrowthCharm）

Bunny Loader **1.4.5.8** 的 Terraria 饰品模组：一件占饰品栏的战士饰品，随 Boss 进度成长，
击败机械三王后可消耗「神圣锭 + 三魂」升级，解锁闪避与吸血。

- 所有数值集中在 [`src/config.js`](src/config.js)，改平衡只动这一个文件
- 所有**不确定的加载器接口**集中在 [`src/adapters/bunnyApi.js`](src/adapters/bunnyApi.js)，全部标 `TODO`
- 属性计算集中在 [`src/stats.js`](src/stats.js) 的 `calculateStats(player, ctx)`
- 离线自测：`node scripts/verify.mjs`（27 项，不需要开游戏）
- 满级表生成：`node scripts/summary.mjs`

> ⚠️ **先读这一段**：本仓库**不包含任何编造的 API 调用**。适配层 `BINDINGS` 里每一项都是 `null`，
> 需要你按 1.4.5.8 的真实接口实现。未实现时 `install()` 会直接抛 `WGC_TODO` 错误，并指出缺哪一项
> —— 不会出现"看起来装上了但属性不涨"的情况。

## 2. 接入加载器（5 步）

1. **填适配层**：打开 `src/adapters/bunnyApi.js`，把 `BINDINGS` 里每个 `null` 换成 1.4.5.8 的真实实现
   （每项注释都写了签名和要做什么）。先用 `api.capabilities()` 看还缺哪些。
2. **挂入口**：加载器初始化后调 `install(loader)`，卸载时调 `uninstall()`。
   若加载器的入口约定名不是 `install`（`onLoad`/`onEnable` 之类，**待确认**），写个同名包装转调即可。
3. **挂升级**：升级/合成界面点"升级"时调 `tryUpgrade(player)`；若加载器有配方系统，
   把配方条件接到这个函数上（配方 API **待确认**，本仓库不假设）。
4. **放贴图**：把 32x32 PNG 放到 `res/WarriorGrowthCharm.png`。
5. **自测**：`node scripts/verify.mjs` → 期望 `27 项通过，0 项失败`。

## 4. 与目标「满级 40% 减伤」的差异（我没有擅自改数值）

按你的配置表实际加总 = **37%**，比目标少 **3 个百分点**。三种改法（都只改 `src/config.js`）：

| 方案 | 改哪里 | 结果 | 说明 |
| --- | --- | --- | --- |
| A. 环境 Boss 改成「每个 +4%」 | `environmentReduction.mode: 'each'` | 37% → **45%**（+8%） | 你要的"只改配置"开关 |
| B. 世纪之花 + 拜月教徒各提到 6.5% | `specialReduction.plantera / lunaticCultist: 0.065` | 37% → **40%** | 只动两条，最接近目标 |
| C. 四柱各提到 3.25% | `specialReduction.pillars.*: 0.0325` | 37% → **40%** | 主线进度更平滑 |

改完重跑 `node scripts/summary.mjs`，表会自动跟着变（`calculateStats` 只读配置，不写死数字）。

## 5. 关键配置说明

| 配置项 | 默认 | 作用 |
| --- | --- | --- |
| `base` | 0.01 / 4 / 0.04 | 初始 1% 减伤 / 4 防御 / 4% 伤害 |
| `genericGrowth.defensePerBoss` | 1 | 每 Boss 防御 |
| `genericGrowth.damagePerBoss` | 0.01 | 每 Boss 伤害（1%） |
| `genericGrowth.dodgePerBoss` | 0.005 | 每 Boss 闪避（0.5%） |
| `genericGrowth.pillarsCountForGenericGrowth` | `true` | **四柱是否计入"每 Boss"成长**：true = 4 根各算 1 个 Boss |
| `genericGrowth.extraBossCount` | 0 | 手动补计不在列表里的 Boss 数量 |
| `genericGrowth.bosses` | 13 条 | 通用 Boss 列表；删/加一条就多/少一个成长位 |
| `environmentReduction.mode` | `'total'` | `'total'` = 三只合计 4%（按已击败数均分，每只 ≈1.33%）；`'each'` = 每只 4% |
| `specialReduction` | 见汇总表 | 世纪之花 / 拜月教徒 / 四柱 / 月亮领主 / 升级后的减伤 |
| `dodge.*` | 0.05 / 0.01 / 0.01 / 0.01 / **0.12** | 闪避各项与硬上限 |
| `upgrade.requiredBosses` | 机械三王 | 升级前置（顺序无关） |
| `upgrade.materials` | 神圣锭 10、三魂各 5 | **待平衡**，只是占位 |
| `upgrade.gains` | +2% 减伤 / +5% 伤害 / +5 防御 | 升级增益，解锁闪避与吸血 |
| `lifesteal.percentOfActualDamage` | 0.01 | 吸血比例（按实际伤害） |
| `lifesteal.cooldownMs` | 200 | 吸血内置冷却 |
| `texture.path` | `res/WarriorGrowthCharm.png` | 贴图路径（换图不改代码） |
| `runtime.pollIntervalMs` | 1000 | 无 Boss 击败事件时的轮询兜底间隔 |

### 规则细节

- **"蠕虫"= 世界吞噬者**，配置里是 `eaterOfWorlds`；**毁灭者 `destroyer` 只作为机械三王升级条件之一**，
  但它同时也在通用 Boss 列表里（每 Boss +1 防御/+1% 伤害）。
- **四柱**：`pillarsCountForGenericGrowth: true` 时，4 根柱子各算 1 个通用 Boss
  （即满级通用 Boss 数是 13，不是 10）。设为 `false` 后满级为 9 个：防御 4+9+5=18、伤害 4%+9%+5%=18%、
  闪避封顶前 15.5%（仍封顶 12%）。减伤不受这个开关影响。
- **闪避**：升级后才解锁；`Math.min(CONFIG.dodge.hardCap, 原始值)`，硬上限 12%。
- **吸血**：只对"实际造成伤害 > 0"的命中生效；冷却期间不回血，但 0 伤害的命中不占冷却。

## 6. 属性为什么不会每帧叠加（实现要点）

1. `calculateStats(player, ctx)` 是**纯函数**：输入"已击败集合 + 是否升级"，输出属性。
   它不持有累加状态，所以同一个 Boss 打几次、读档几次，结果都一样。
2. `accessory.js` 每次更新严格 **先撤销上一次加成，再应用新加成**：
   保存 `applyStatModifiers` 的返回值（handle），下次先 `removeStatModifiers(handle)`。
3. **指纹短路**：属性值没变（`statsSignature` 相同）就直接跳过撤销/重放，避免高频事件抖动。
4. **卸下即清零**：`onUnequip` 撤销全部加成，并把闪避/吸血解锁状态一起复位；
   游戏内临时加成没了，但 Boss 进度/升级标记仍在（持久化由适配层负责）。

**C. 如果 Bunny Loader 没有「命中 NPC」钩子（吸血的替代方案）**

吸血不接钩子也能做，按可靠性排序：

1. **伤害数字/暴击回调**：若加载器提供"伤害结算完成"回调（`onDamageDealt` 之类），
   在那里拿最终伤害 —— 最准，等价于 `onHitNpc`。
2. **玩家攻击冷却轮询**：记录玩家最近一次"攻击动作"，攻击后 100ms 内若目标血量下降则按差值回血 ——
   能工作，但多段武器会分成多口，冷却 200ms 正好压住。
3. **降级方案**：把吸血改成"击杀回复固定血量"或"攻击命中后按面板 DPS 估算"，
   并在 tooltip 里注明"估算值"。
4. **最保守方案**：关掉吸血（`lifesteal.enabled: false`），其余属性不受影响。

不给"没有钩子却假装能精确到每一下"的实现 —— 那会变成数值漂移。
